# 目标词语境生成 P0 基线结果（2026-10-08）

## 协议与数据

- 固定 24 个任务：A2/B1/B2 × 两种新词与复习词配比 × 四个主题；每题 6 个目标词。
- A 为普通提示生成；B 为结构化提示生成；C 复用 B 的首稿，未达标时根据失败原因重写一次。三组均使用 `deepseek-flash`、官方 DeepSeek API、非思考模式。每个任务每组仅生成一次。
- 英文长度目标为 350–450 词；参照当前业务规则，315–495 词算篇幅验收通过。综合通过还要求目标词出现次数、平均句长与非目标低频词比例达标，并包含中文译文。目标词按正文中的实际词形计数；自动检查不能证明内容自然或教学效果。
- 原始 `manifest.json`、72 条请求响应 `runs.jsonl`、逐条 `metrics.csv`、`summary.json` 与盲评表在 `full.local/`。本目录被 Git 忽略，须本地保留作为实验原始证据。72 条响应均正常解析，没有 API 请求错误。

## 自动指标

| 指标（24 题） | A 普通提示 | B 结构化提示 | C 结构化提示加一次定向重写 |
| --- | ---: | ---: | ---: |
| 目标词次数达标 | 12 | 24 | 24 |
| 篇幅达标 | 19 | 8 | 8 |
| 综合验收通过 | 9 | 6 | 6 |
| 平均 API Token / 题 | 928 | 1,005 | 2,033 |
| 平均请求耗时 / 题 | 9.79 秒 | 9.42 秒 | 15.45 秒 |

成对比较：A 与 B 有 3 题都通过、6 题仅 A 通过、3 题仅 B 通过、12 题都未通过。B 与 C 的综合通过状态在 24 题中完全相同。C 实际触发 18 次重写；其中 16 次英文正文与 B 完全相同，另 2 次英文正文有变化，但均未解决原有违规项。C 的 Token 和耗时包含 B 首稿及可能发生的重写，不能再与 B 的总量相加计算实际消耗。

主要失败原因：A 有 12 题目标词次数不足、5 题篇幅不足、3 题低频词比例超限；B 有 16 题篇幅不足、6 题低频词比例超限、1 题平均句长不合要求；C 对应数值未改变。失败原因可在同一篇文章中重叠。B/C 的 16 个篇幅失败均为不足 315 词，未出现超长。

## 可得结论与下一步

结构化提示稳定提高了本批任务的**目标词次数达标率**，但当前整体验收率低于普通提示。现有定向重写提示在这批任务中未带来综合验收收益，同时增加调用成本。不能把目标词覆盖的提升写成文章整体质量提升，也不能声称 C 优于 B。样本量只有 24 题、每题仅一次生成，结论限于本次模型、任务和提示版本。

下一轮应优先研究 B 的篇幅不足，以及 C 为何复制原正文：在开发任务上修改篇幅规划与失败原因到具体修改动作的提示；冻结新版本后用未参与调参的任务验证。不得用本轮 24 题反复挑选最优提示再把同一批结果当独立测试集。两名评分者需对 `blind_rating_sheet.csv` 中的文章分别评分自然度、连贯性、目标词使用与译文忠实度，完成后再揭盲。人工评分前不作语言质量或学习效果结论。

## 与生产系统的边界

本实验用冻结的生产风格提示和独立评价器直接请求模型，没有调用 Java 业务服务、自动选词、自动补全 `[[词形|词元]]` 标记或数据库入库。它检验生成与验收设计的方向，不能等同于在线端到端通过率。业务代码在重写后重新检查难度的漏检已修正，并由 `ContextStoryServiceImplTest` 的回归用例覆盖。
