# P0 实验与生产服务口径核对（2026-10-08）

## 模型请求

两者均使用 `deepseek-flash`、`https://api.deepseek.com/chat/completions`、`temperature=0.3`、`max_tokens=5000` 和 `thinking={"type":"disabled"}`。生产 `AiGatewayServiceImpl` 另发送 `enable_thinking=false`；P0 脚本不发送此兼容字段。生产模型配置仍以账号实际保存项为准，P0 显式指定模型 ID 与 API Host。

## 提示差异

- P0 的 B 组是**生产风格的压缩版**提示；生产版系统提示包含更详细的自然度、标记与中译要求，用户提示含 `examFocus`、目标词跨文章分布以及 JSON 示例。
- P0 的 C 组用英文短标签（如 `length`、`rare_vocabulary`）告知失败原因；生产版把词数、目标词缺口等用中文错误文本传给重写提示。生产版原有重写要求“保留原有故事”，可能诱使模型复制正文；P0 的 18 次重写中有 16 次正文完全相同，但不能直接推断生产版相同比例。
- P1 曾试验给首稿增加段落词数预算，但开发集结果不佳，最终保留原首稿。修复阶段按失败类型选择追加新段落或重新生成，独立实验的 B/C 复用同一首稿。实验脚本是生产流程的适配实现，仍有数据库词频、自动补标记等差异；运行清单记录服务源码指纹。

## 评价差异

- 生产代码先用 `StoryNlpUtil.autoFillMissingMarkers` 补齐未标记目标词，再按标记计数；P0 评价器直接对可见英文词形计数。P0 的 B/C 各有 22/24 个任务原始输出的目标词标记次数已经满足要求，剩余 2 个任务生产代码可能通过自动补标记修复。
- 生产与 P0 均按英文正文词数的 90%–110% 验收篇幅。六词任务为 350–450 词，实际验收区间 315–495 词。B2 平均句长下限 10 词、上限 31 词；A2/B1 仅有上限。
- P0 在 ECDICT 覆盖不足 70% 时把低频指标设为不可验证并拒绝综合通过；生产服务在词频缺失时返回 `null`，按现有难度策略继续由句长决定。P0 正式实验的 72 条记录均未出现该未知情况，所以该差异不改变 P0 数值。
- 生产词形归一化使用 `StoryNlpUtil.approximateLemmatize` 和数据库 `frequency_rank`；P0 使用独立 Python 近似词形规则和 `material/ecdict.csv`。独立指标适合固定协议比较，不能声称它等于数据库入库验收率。
- P0 旧词形规则把 `was`、`said` 等常见不规则词形误判为低频词。P1 同步修正 Java 与独立评价器，并把 P0 原始口径及修正后敏感性分析同时保留。P0 原始 A/B/C 综合通过数为 9/6/6，修正词形规则后为 10/7/7；这不是重新生成的实验结果。

## 结论边界

P0 的 6/24 是压缩提示、独立评价器下的 B/C 结果，不能作线上系统的实测通过率。P1 报告将把“独立实验规则通过率”和“生产服务的业务校验”分开说明，并保留输入、提示、模型参数、评价器版本和原始响应。
