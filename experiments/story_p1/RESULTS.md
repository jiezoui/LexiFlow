# P1 目标词语境生成优化结果（2026-10-08）

## 实现与实验范围

生产服务保留原首稿提示，改为按验收失败类型修复：仅篇幅不足时生成并追加英中对应段落；其他失败时重新生成文章；新稿如仍仅篇幅不足，可再追加一次。每次候选都重新检查目标词、篇幅、句长、非目标低频词比例和中文译文，最多两次修复调用，未达标不入库。词频检测增加常见不规则词形归一化和句中人名过滤。Java 定向回归测试 22 项通过。

独立实验使用固定的 24 道新题，覆盖 A2/B1/B2、两种新旧词配比和 library、journey、market、sports 四个新主题；目标词与 P0 开发题不重合。三组使用同一 `deepseek-flash` 模型、`temperature=0.3`、`max_tokens=5000`、关闭思考模式。A 为普通提示；B 为原结构化首稿加旧完整改写；C 与 B **共用完全相同的首稿**，改用新修复策略。独立评价器按目标词次数、315–495 英文词、级别句长、ECDICT 非目标低频词比例及中文译文存在性综合验收。每题只运行一次；无 API 请求错误。

C 相比 B 多通过 6 题，即本批任务的综合通过率高 25 个百分点；成对结果是 18 题两组都通过、6 题仅 C 通过、0 题仅 B 通过。六个新增通过案例中，五个原首稿仅篇幅不足，追加段落后通过；一个原首稿目标词次数不足，重新生成后通过。C 平均每题比 B 少 124.1 Token（约 6.6%），请求耗时少 0.24 秒（约 2.0%）；这是本次 API 运行的观测值，不能保证其他时间或服务负载下也更快。C 的调用成本包含 B/C 共用的首稿成本，代表该策略单独为一位用户运行时的平均成本。

按级别看，A2/B1/B2 的 C 组均为 8/8；B 分别为 4/8、6/8、8/8。预先约定的工程目标为 C 至少 16/24、比 A 和 B 各多至少 4 题、目标词至少 22/24、平均 Token 不超过 B 的两倍，本次均达到。这些目标是工程判断线，不构成统计显著性或跨模型泛化证明。

## 开发集与 P0 口径

P0 旧 24 题仅用于诊断和开发，不计入上表。最终策略在这批开发题上复核的 B/C 综合通过数为 15/24 和 22/24；C 仍有两题篇幅不足、一题低频词比例超限，其中失败项可重叠。此前“给首稿分配段落词数”的试验效果不佳，因此没有进入最终策略。

P0 的原始独立评价器将 `was`、`said` 等常见不规则词形误判为低频词。保留 P0 原始 A/B/C 综合通过数 9/6/6，不改原始响应；用修正词形规则对同一批响应做敏感性重评后为 10/7/7。P0 用压缩生产风格提示，P1 使用更接近生产服务的完整提示与新题，**不能**把两轮绝对数值直接作为前后提升幅度。P1 的 B/C 同题同首稿比较才是本次修复策略的主要证据。

## 局限与待完成评价

自动通过率证明约束执行情况，不证明文章自然、目标词使用恰当、译文忠实或学习效果。独立测试只有 24 题、每题一次生成，主题和模型固定，结果存在模型随机性。低频词比例依赖 ECDICT 排名和启发式词形归一化，不是标准 CEFR 测评。实验脚本不调用 Java 服务、数据库选词和自动补标记；线上完整链路尚未在本轮做真实调用验收。已有 Java 单元测试覆盖修复、复检与失败拒绝入库。

预先固定的 12 题 × 三组，共 36 篇盲评材料已生成于 `holdout_v3.local/blind_rating_sheet.csv`；两位独立评分者尚未打分。完成自然度、连贯性、目标词使用和译文忠实度评分前，技术报告应只报告**自动规则通过率**，不要写“语言质量提高”或“教学效果提高”。

原始证据在被 Git 忽略的 `holdout_v3.local/`：`manifest.json`、`runs.jsonl`（72 条分组记录）、`metrics.csv`、`summary.json`、盲评表及揭盲映射。清单中的 runner、协议、修复策略和题库 SHA-256 已核对与当前文件一致。复现步骤见 [README](README.md)。
