# LexiFlow 页面分布与信息架构

> **TL;DR**
> 全站 38 个路由，一级导航只有 5 项：今日 / 词书 / 生词本 / 视频 / 阅读。**没有「复习」这一项**——复习在「今日」里，因为全站只允许存在一个复习入口。
> `/study` 不是一个静态页面，是会话调度中枢：认词筛选 → 新词学习 → 复习 → 检测，在同一个路由下用组件切换，进度条不断，中途关掉浏览器明天能接着做。
> 五个页面单独详设：`/`（空状态决定新用户留不留）、`/study`（调度）、`/study/typing`（FSRS rating 的采集口）、`/videos/:id`（全站最复杂）、`/settings/engine`（两层引擎必须分清）。

### 1.1 对给定路由规划的调整与理由

| 调整 | 理由 |
|---|---|
| **加 `/auth/reset`** | `/auth/forgot` 只负责「填邮箱发信」，邮件里的链接必须落到一个带 token 的独立页面。两件事合一个路由会让 token 校验失败态和表单态混在一起 |
| **`/study` 本身不渲染内容，只做重定向** | 它是调度器：进入时读会话状态，`router.replace` 到 `triage/learn/review/...` 中的正确一环。让它可停留就必然出现「用户停在 /study 看着一个假的开始按钮」这种冗余一步 |
| **加 `/practice` 索引页** | `dictation` / `shadowing` 都需要先选题源（哪个视频、哪一段），没有索引页就只能从视频页跳进来，练习模块变成视频的附属品。S5 的验收要求「从任意已导入视频一键生成 20 句听打」，索引页承载这个「任意」 |
| **加 `/plan`（S6）** | roadmap S6 有「计划执行看板」这一交付项，且要求「任务项可点击直达功能页」。塞进 `/stats` 会让统计页承担两种职责（回顾 vs 前瞻） |
| **加 `/assistant`（S7）** | S7 的语音对话需要一个能长驻的会话页面（麦克风权限、打断、对话记忆），不能做成弹层 |
| **加 `/settings/shortcuts`** | 架构文档 §6.5 明确「绑定表从 settings store 读，支持用户自定义」。视频页 + 复习页 + 打字页三套快捷键，冲突需要一个集中改的地方 |
| **加 `/settings/plugin`（S4）** | 插件的登录态、划词开关、高亮开关需要 Web 端有对应设置页（插件 popup 太小放不下） |
| **`/vocab/known` 保留为独立路由而非 tab** | 已知词库有独立的批量操作（批量取消已知、按词频段批量标记），操作面板和生词本不同；独立路由也方便从 `/study/triage` 的结果页直接跳过来复查误判 |
| **不设 `/dict/:word` 查词页** | 查词是最高频动作（产品 §4.3），跳页就打断精听节奏。查词统一走 `WordPopover` 弹层 + `Cmd+K`；需要长驻查看的场景已有 `/vocab/:wordId` |
| **不设 `/review` 路由** | 铁律。`/review` 一旦存在，导航栏就会长出「复习」项，词书复习与生词本复习的分裂就从 URL 开始了 |
| **字幕上传不给路由** | `/videos/:id` 内用抽屉完成。给它 `/videos/:id/subtitle` 会让用户上传完落到一个孤岛页，还得再点回视频 |

**关键交互**

| 交互 | 行为 |
|---|---|
| 「开始今日学习」 | 唯一主 CTA，跳 `/study`。**页面上不允许出现第二个复习入口**——「词书 42%」卡片里只有「切换主词书 / 调每日量」，绝不放「背这本」按钮 |
| 数字分解 | 「复习 47」hover 展开来源分布（CET6 15 / 视频 26 / 文章 6）。分解只是**信息**，不是**入口**，点击任何一段都不能单独进入该来源的队列 |
| 中断续做 | 若 `studySession` 有未完成会话且日期是今天，主 CTA 文案变「继续（第 23/67 张）」 |
| 最近观看续播 | 点缩略图直接 `/videos/:id?t=252`，从上次时间戳起播 |
| 跨日结转 | 昨日未完成的复习会被 FSRS 计入今日 overdue，`47` 里含 overdue 时旁边加一个「含逾期 12」的灰字提示，不做红色告警（负反馈会赶走人） |

**状态与空状态**

| 状态 | 表现 |
|---|---|
| 加载中 | 骨架屏，ProgressRing 位置给圆形 skeleton，不给 spinner（避免闪烁） |
| **全新用户**（无词书、无视频、无生词） | **整页替换成引导卡**，不显示 0/0 的空进度环。文案策略：把「你还没有数据」翻译成「选一本词书，2 分钟后开始第一次学习」，主 CTA 直跳 `/onboarding`。绝不显示四个空卡片让用户自己猜下一步 |

**快捷键**：`Enter` 开始今日学习 · `Cmd/Ctrl+K` 全局搜索 · `G` 后跟 `W/V/R/S` 跳词书/视频/阅读/统计（vim 风格 goto 序列）

**性能要点**：首屏只发 3 个请求（`/api/study/today`、`/api/stats/summary`、`/api/media/recent`），并行发出，各自独立渲染；heatmap 数据（84 天 × 1 数字）走 stats 预聚合表，不实时算；ProgressRing 用 SVG `stroke-dashoffset`，不引图表库；最近观看缩略图用平台 CDN 直链 + `loading="lazy"`。

**移动端适配**：单列纵向堆叠，顺序 = 任务卡 → 词书进度 → 最近观看 → heatmap（横向可滑）→ 快速入口收进底部 FAB。主 CTA 变**吸底全宽按钮**，滚动时始终可见——移动端来这一页只为点这一个按钮。侧边栏收成底部 TabBar（今日/词书/生词本/视频/更多）。

### 3.2 `/study` 今日学习（调度中枢）

这不是页面，是一个**有限状态机 + 单页会话容器**。用户从点「开始」到看到小结，**URL 的 path 段会变但页面不卸载**，顶部进度条不断，因为一旦感觉「跳走了」，会话的连贯感就断了。

**会话编排**

```
进入 /study
   │
   ├─► 读 studySession store（localStorage 持久化） ── 有今日未完成会话？
   │        │是 → 恢复到 phase + index，主区渲染对应组件
   │        │否 → 拉 /api/study/today 组装队列 → 建新会话
   ▼
┌────────────────────────────── 会话队列构成 ──────────────────────────────┐
│  Phase 1  TRIAGE    仅当本次有「从未接触的新词」且用户开了筛选：            │
│                     新词候选 × 2 倍量 → 认识/不认识 → 认识的写 known_word  │
│  Phase 2  LEARN     筛出的不认识新词，逐张学习卡（无评分，只是首次接触）     │
│  Phase 3  REVIEW    FSRS 到期队列。★ 混合来源：source=WORDBOOK 的词和       │
│                     source=VIDEO/ARTICLE/PLUGIN 的词按 due_at 排序，        │
│                     完全平等，不分组、不分段、不显示分隔线                   │
│  Phase 4  TEST      检测环。每张卡按「该词当前状态 + 用户默认检测模式」派发   │
│                     到 typing / spell / quiz 之一（见下表）                 │
│  Phase 5  DONE      小结 → /study/done                                    │
└──────────────────────────────────────────────────────────────────────────┘
```

**Phase 4 不是独立阶段，是嵌在 REVIEW 里的检测形态**——这一点很关键：`/study/typing` 既可以作为复习卡的检测形态被调度器派发，也可以被用户从 `/vocab` 主动进入练某一批词。派发规则：

| 卡片情况 | 派发到 | 理由 |
|---|---|---|
| 新学当天的词（LEARNING 状态第 1 次） | `quiz` 选择题 | 刚见过，默写必挫败 |
| REVIEW 状态、间隔 < 7 天 | `typing` 打字默写 | 主力检测手段，信号最高保真 |
| REVIEW 状态、间隔 ≥ 7 天 | `spell` 听音拼写 | 加难度，测音形对应 |
| 有原声语境快照的词 | 卡面强制用 `AudioSnippet` 播那 3 秒 | 差异化的物理载体 |
| 用户在设置里锁定了模式 | 一律用锁定的 | 设置优先于自动派发 |

**关键交互**

| 交互 | 行为 |
|---|---|
| Phase 切换 | `<Transition mode="out-in">` 淡入淡出 120ms，会话头/操作条不动。**不用路由过渡动画**，视觉上必须是同一个页面在换内容 |

| 超时暂停 | 无输入 3 分钟自动暂停计时器（避免「今日学习 4 小时」这种脏数据），但不弹遮罩打扰 |

| 状态 | 表现 |
|---|---|
| 今日队列为空（都做完了） | 直接 `replace` 到 `/study/done`，不显示空的会话容器 |
| 完全没有可学的词（没开词书 + 生词本空） | 拦在 `/` 的空状态，不让进 `/study` |
| 队列加载失败 | 全屏错误态 + 重试；若本地有 `queueIds` 缓存则允许「用本地缓存队列离线学习」 |
| 只有新词没有复习 | 分段进度条只显示「筛选▏学习」两段，不显示空的复习段 |

**快捷键**：`Space` 显示答案/下一张 · `1/2/3/4` = Again/Hard/Good/Easy · `←` 上一张（仅 LEARN）· `S` 跳过 · `A` 播发音 · `C` 播原声语境 · `Esc` 退出确认 · `?` 快捷键浮层

**性能要点**：队列一次拉全（67 张的元数据 < 40KB），卡片详情（例句、语境快照、AI 助记）**预取下一张**，保证翻卡 0 延迟；`keep-alive` 缓存已渲染过的 phase 组件；音频用 `AudioSnippet` 的预加载池（当前 + 后 2 张）；答题请求走独立的低优先级 axios 实例，不参与全局 loading 遮罩。

**移动端适配**：这是**移动优先页面**。卡片撑满视口；评分按钮变底部四宫格大按钮（拇指区）；显示答案改为「点卡面任意处」；左右滑手势 = 上一张/下一张；打字类检测在移动端默认降级为 `quiz`（虚拟键盘打字体验差），但在设置里可强制开启。

### 3.3 `/study/typing` 打字默写

FSRS 的 rating 质量决定整个调度器的质量，而这一页是 rating 的主要采集口。「点一下我记得」会骗人，手指不会。


**逐字母校验的视觉反馈**

| 状态 | 视觉 | 说明 |
|---|---|---|
| 待输入 | 下划线 `▔`，中性灰 | 槽位数量 = 单词长度，**默认显示长度**（不显示长度会让长词变成猜谜）。词长 > 12 时槽位分组显示 |
| 正确 | 字母显示，中性灰（不是绿色） | 正确是常态，不该有正反馈噪音。绿色留给整词通过 |
| 错误 | 红色 + 横向抖动 120ms + 短促错误音 | 抖动只抖那一个槽位，不抖整行（整行抖会晃到眼睛） |
| 当前光标位 | 槽位下划线加粗闪烁 | 只有一个 |
| 整词通过 | 全行绿色 → 上浮淡出 → 下一张 | 250ms，不给「继续」按钮 |

**输入实现要点**：一个透明的 `<input>` 承接真实输入（保证输入法/移动键盘正常），槽位是渲染层。**不用 8 个独立 input**——退格跨格、粘贴、输入法组合态都会失控。

**关键交互**

| 交互 | 行为 |
|---|---|
| 打错 | 该字母标红抖动，**不自动清空**，光标停在错误位，用户必须退格改。自动清空会掩盖「他其实只错了最后一个字母」这个信息 |
| 退格 | 记 `backspaceCount`。退格本身不惩罚（手滑很常见），但它是 rating 的降级信号之一 |
| 首字母提示 | 填入第 1 个字母并标为 `hinted`，`hintUsed = true` |
| 长度提示 | 默认已给长度；此按钮在「盲打模式」（设置里可开，不显示槽位数）下才出现 |
| 连击 | 连续无提示无错误通过累加，仅在会话头显示数字，**不做特效不做音效不入库**（Non-goals 里游戏化只保留 streak） |
| 节奏 | 记录首字延迟 `firstKeyMs` 与总耗时 `totalMs`。首字延迟是「想起来了没有」，总耗时含打字速度噪音——**判定主要看首字延迟** |
| 输入法冲突 | `compositionstart` 事件触发 → 顶部黄条提示 + 输入框边框变黄。检测到 `isComposing` 期间的按键全部忽略，不写入槽位。兼容模式：改用 `keydown` 的 `event.code` 直接映射 A-Z（绕过输入法），代价是不支持连字符词 |
| 含连字符/空格的词 | 槽位预填 `-` / 空格且不可编辑，光标自动跳过 |

**FSRS rating 映射**

```
输入 → 判定（前端算，后端二次校验防作弊/防脏数据）

hintUsed == true                      → Hard    (3 挡里的降级，不是 Again)
errorCount == 0 && backspaceCount == 0
   && firstKeyMs <= 1500              → Easy
errorCount == 0                       → Good    （慢，或有退格）
errorCount >= 1 && 最终打对            → Good→Hard 降一级（错 1 次 Hard；错 ≥2 次 Again）
放弃 / 超时 20s 未完成                 → Again
```

阈值 `1500ms` 与 `20s` 放 `settings/study`，因为打字速度个体差异极大（60 wpm 和 25 wpm 用同一阈值会让慢手永远拿不到 Easy）。首次使用时用 onboarding 里的一次校准打字取基线。

**状态与空状态**：无待默写词时不该进这一页（调度器负责）；直接从 `/vocab` 批量选词进来时若选中集为空，按钮置灰并提示先选词；音频加载失败时 `AudioSnippet` 退化为纯文本语境，不阻塞答题。

**快捷键**：`A-Z` 输入 · `Backspace` 退格 · `H` 首字母 · `L` 长度 · `Esc` 放弃本词 · `Tab` 播发音 · `Ctrl+Enter` 强制提交当前输入 · `?` 帮助。**注意 `H`/`L` 与字母输入冲突**——解法：提示键改为 `Alt+H` / `Alt+L`，界面按钮上标注的也是 `Alt+H`。

**性能要点**：keydown 处理必须 < 8ms（一帧内），槽位状态用 `shallowRef` 数组 + 只更新变化的那一项；抖动动画走 CSS `animation` 不走 JS；错误音效预加载并复用同一个 `AudioBuffer`（不要每次 `new Audio()`）；不在 keydown 里做任何网络请求。

**移动端适配**：**移动优先**。槽位字号放大到 28px；输入框 `autocapitalize="off" autocorrect="off" spellcheck="false" inputmode="text"`（必须全关，否则自动纠错会把答案填了）；虚拟键盘弹出时用 `visualViewport` API 把语境区收起、槽位区上移，保证槽位不被键盘挡；提示按钮上移到槽位下方（键盘上沿之上）；连击数字隐藏。移动端默认阈值放宽（`firstKeyMs <= 2500`）。

**字幕与播放器时间轴同步**

严格按架构文档 §6.4：

| 要点 | 做法 |
|---|---|
| 驱动 | `requestAnimationFrame` 而非 `setInterval`。切后台自动停，无累积漂移 |
| **不进响应式** | `player.getCurrentTime()` 的返回值绝不写入 reactive state。每帧只做 `binarySearchCue(cues, t)`（O(log n)） |
| 只在切句时触碰 DOM | `idx !== lastCueIdx` 才 `classList.remove/add('active')` + `scrollIntoViewIfNeeded`，并且**只有此刻**写一次 `playerStore.currentCueId`（频率 ≈ 每句一次，约 0.2 次/秒） |
| 容差 | iframe API 时间精度 ±100~250ms，切句判定加 ~80ms 容差，避免边界来回抖 |
| 状态机 | `IDLE / LOADING / PLAYING / PAUSED / SEEKING / ENDED` 显式状态机；`SEEKING` 期间忽略 `getCurrentTime()`，否则 seek 抖动会误触发切句 |
| 播放器时间是唯一真相 | 双语字幕以**原文轨为唯一基准时间轴**（§5.4），译文轨按区间重叠度贪心匹配到原文 cue 上，绝不用译文轨的时间戳 |
| 进度条刻度 | cue 分段刻度是一次性渲染的静态 SVG（800 条 = 800 个 1px `<rect>`），不随播放更新；播放头是单独一个 `transform: translateX()` 的元素，走 rAF 直接改 style |

**四层高亮（颜色必须区分得开）**

| 层 | 视觉 | 数据源 |
|---|---|---|
| 当前句 active | 侧栏行背景浅色块 + 左侧竖条 | `playerStore.currentCueId` |
| 已在生词本的词 | 黄色底纹 | `vocabStore.lemmaSet`（架构 §6.2：**所有高亮的唯一数据源**） |
| **正在背的词**（词书在学） | 蓝色下划波浪线 + 行尾 `CET6·3` 计数徽标 | `vocabStore.studyingLemmaSet`（另一个 Set） |
| 已知词 | 无标记（默认态） | `known_word` |

黄 vs 蓝的区分是产品 §3.1 反向链路的全部价值所在：用户要能一眼看出「这句话里有 3 个我正在背的 CET6 词」。徽标点击 → 高亮那 3 个词并弹一个「你昨天背过它」的小提示。

**关键交互**

| 交互 | 行为 |
|---|---|
| 点词 | `useWordSelection` 把 `Range` 映射到预分词的 token（§5.7 tokens 预分词落库，前端不做分词）→ lemma → 本地词典查（毫秒返回）→ 弹层。AI 语境释义异步补进弹层，**不阻塞** |
| 弹层定位 | 以被点 token 的 `getBoundingClientRect()` 为锚，优先向下弹；下方空间 < 弹层高则向上；左右溢出时贴边并移动箭头位置。**弹层永不遮挡当前字幕行**（这是精听页最容易犯的错） |
| 划词查短语 | 拖选跨 token → 尝试 `dict_phrase` 查询（`give up` / `look forward to`），命中则弹短语卡，避免被拆成单词入库（§4.2） |
| 单句循环 | rAF 内 `t >= loopEnd` → `seekTo(loopStart, true)`，不用 `setTimeout`（seek 会打乱定时）。可设遍数与间隔；循环中切句快捷键自动把循环区间平移到新句 |
| 逐句跳转 | `←/→` = 上/下句，`seekTo(cue.start)`。精听的操作单位是句，不是秒 |
| 字幕三档 | `1` 双语 / `2` 仅英文 / `3` 听写模式（全隐藏 + 显示 `▁▁▁ ▁▁ ▁▁▁▁` 占位保留词数与长度轮廓，比纯空白有用得多）。当前档位持久化到 `settings` store |
| 变速 | 0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0。**持久化**——精听用户基本固定在 0.75 |
| 收藏句 | `S` 存 `saved_sentence`，行尾出现书签图标。收藏的句子是 `/practice/dictation` 的题源 |
| 跳听打 | 「🎧 听写」把当前 ±10 句打包成练习集，跳 `/practice/dictation?source=video:123&from=cue_88`。**离开时保存播放进度** |
| 字幕缺失 | 顶部黄条「这个视频没有字幕」+ 三个出路：上传 `.srt/.vtt/.ass` / 试试自动抓取 / 用 ASR 生成（走 ai 模块 ASR capability，异步 job + 进度条） |
| 译文缺失 | 「翻译整轨字幕」按钮 → 走机翻链批量翻译 + 缓存（S3 要求：第二次打开 0 次调用），`useAsyncJob` 轮询进度 |

**状态与空状态**

| 状态 | 表现 |
|---|---|
| 播放器加载中 | 播放区骨架 + 侧栏字幕已可读（字幕来自自己后端，比 iframe 快得多，先给内容） |
| iframe 加载失败 / 需要代理 | 明确区分「网络不通」和「视频被作者限制嵌入」两种错误，前者给「检查代理」，后者给「去原站看」。**不要统一报「加载失败」** |
| 无字幕无译文 | 侧栏空状态 = 上传/抓取/ASR 三个入口，不是一句「暂无数据」 |
| 本地视频文件 | `<video>` + Object URL，页面刷新后 URL 失效 → 提示「重新选择文件」（不要静默黑屏） |
| 采词数为 0 | 侧栏「采词」计数区显示引导：点字幕里任意词试试 |

**快捷键表**

| 键 | 动作 | 键 | 动作 |
|---|---|---|---|
| `Space` | 播放 / 暂停 | `1` | 双语字幕 |
| `←` / `→` | 上一句 / 下一句 | `2` | 仅英文 |
| `↑` / `↓` | 侧栏滚动（不改播放） | `3` | 听写模式（隐藏） |
| `R` | 重播当前句 | `S` | 收藏当前句 |
| `L` | 单句循环开/关 | `D` | 把选中/上一个查的词加生词本 |
| `[` / `]` | 减速 / 加速 | `T` | 译文显隐（独立于 1/2/3） |

| `/` | 聚焦字幕搜索 | `?` | 快捷键浮层 |

**性能要点**（800 条 cue 是常态，20 分钟播客可到 1500 条）

- 侧栏虚拟滚动，仅渲染视窗 ±20 行；**但当前句必须始终在渲染范围内**（切句时若不在，强制扩展渲染窗口再滚动）。
- cue 列表放组件局部 `shallowRef`，**不进 store**（§6.2 通用规则：store 不放能按需拉取的大对象）。
- 高亮词的标注在**服务端预计算**：`subtitle_cue.tokens` 落库时就带 lemma，前端只做 `lemmaSet.has(lemma)` 的 Set 查找，不做正则扫描。
- 每行 cue 用 `v-memo="[cue.id, isActive, highlightVersion]"` 冻结；`highlightVersion` 在生词本增删时 +1，触发一次全量重算（低频）。
- 二分查找的 cue 数组按 `start` 预排序，构建时做一次，不每帧排序。
- 字幕搜索用本地过滤（cue 已在内存），不打后端。

**移动端适配**：三区改**上下两区 + 底部抽屉**。播放器吸顶（`position: sticky`），侧栏字幕变成播放器下方的主体列表（全宽），词卡弹层改为**底部 Sheet**（不做 popover 定位，移动端 popover 必然遮挡）。快捷键全部失效，改手势：单击字幕行跳转、长按词查词、左右滑 = 上下句、双击播放区 = 单句循环。字幕档位和变速收进播放器右上角的 `⚙` 菜单。**移动端不做听写模式**（对着小屏做听写不现实），但保留三档切换里的前两档。

**移动端适配**：低优先级。两层折叠为可展开的 Accordion；拖拽排序在移动端换成「上移/下移」按钮（移动端 HTML5 drag 不可靠）；ProviderCard 单列全宽；用量表横向滚动。

### 4.2 一级导航只有 5 项，且**没有「复习」**

| 一级项 | 路由 | 为什么在一级 |
|---|---|---|
| 今日 | `/` | 每天必来，且它是唯一的学习入口 |
| 词书 | `/wordbooks` | 入口 A 的门 |
| 生词本 | `/vocab` | 数据资产的门，用户要能随时确认「我的词都在」 |
| 视频 | `/videos` | 入口 B 的主体 |
| 阅读 | `/reading` | 入口 B 的第二类语料 |

**为什么没有「复习」——这是全站最重要的一条导航决策：**

产品铁律是「一个 `user_word` 表、一个 `due_at`、一个『今日复习』入口」。如果导航里有「复习」这一项，那么：

1. 它和「今日」职责重叠 —— 用户会问「今日里的复习和复习页的复习是同一批词吗」，一旦产生这个疑问，两条线合一的心智模型就崩了。
2. 有了「复习」入口，词书详情页就会想放「复习这本」，生词本页就会想放「复习生词」，这正是被明令禁止的两个按钮。
3. 「复习」是**动作**不是**空间**。导航栏应该是空间（我的词书、我的视频），动作归 CTA。

具体守法：

- **词书详情页 (`/wordbooks/:id`)** 的主按钮是「加入学习 / 调整每日量」，不是「开始背」。已在学的词书显示「已加入 · 每日 15 词」+ 一句「今天的 15 个词在『今日』里」，并给一个跳 `/` 的文字链。
- **生词本页 (`/vocab`)** 的批量操作里有「加入今日额外练习」，这不是复习入口——它进的是 `/study/typing?ids=...` 的**练习**模式，产生的 rating 照样写回 FSRS，但**不影响今日的到期队列**。文案上必须叫「练习」不叫「复习」。
- **`/study` 之外任何页面都不允许出现「复习」二字的按钮。**

「练习」放在二级（更多）里，因为它是可选的补充训练，不是每日主干。

### 4.3 全局搜索（Cmd/Ctrl+K）

```
┌────────────────────────────────────────────────────────────┐
│ 🔍 trig                                              Esc   │
├────────────────────────────────────────────────────────────┤
│ 单词                                                        │
│   ▸ trigger    /ˈtrɪɡə(r)/  n.扳机；v.引发    [在生词本 ·黄]│
│     trigonometry  n.三角学                                  │
│ 词书                                                        │
│     CET6 核心词汇（含 trigger）· 已加入 42%                  │
│ 视频                                                        │
│     TED · How to speak…  字幕命中 2 处 → 04:12, 07:31       │
│ 文章                                                        │
│     What Makes a Trigger  · 生词率 3.2%                     │
├────────────────────────────────────────────────────────────┤
│ ↑↓ 选择   ⏎ 打开   ⌘⏎ 加入生词本   Tab 切分类               │
└────────────────────────────────────────────────────────────┘
```

- **单词区永远排第一**，因为查词是最高频动作。走本地词典（`dict_entry` 前缀查询 + Redis 缓存），目标 P95 < 30ms。
- 视频/文章命中**要给字幕内命中位置**，点击直接跳到那一秒——这是「我记得在哪个视频里听过这个词」的入口。
- 输入 debounce 150ms；单词区在 60ms 内先出本地缓存的结果，其余分类的后端结果到了再补进来（分区独立渲染）。
- `⌘⏎` 直接加生词本（无语境快照，`source = MANUAL`）。

## 6. 状态管理（Pinia store）

遵循架构文档 §6.2：全局常驻 4 个，随页面挂载 3 个，store 不放能按需拉取的大对象。

| store | 生命周期 | 职责 | 持久化 |
|---|---|---|---|
| `auth` | 全局常驻 | 当前用户、access token（**仅内存**）、onboarding 完成标记 | ❌ access token 绝不入 localStorage（架构 §7）；refresh 走 httpOnly cookie / 内存 |
| `settings` | 全局常驻 | 主题、字幕显隐档位、播放速率、快捷键映射、每日量、默认检测模式、打字阈值、region | ✅ **localStorage**（服务端也存一份，登录时以服务端为准做一次 merge；纯 UI 偏好如字幕档位只存本地） |
| `vocabulary` | 全局常驻 | `lemmaSet: Set<string>`（生词）+ `studyingLemmaSet: Set<string>`（词书在学）+ `knownSet`。**所有高亮的唯一数据源**；增删时局部更新 Set，不重拉全量 | ✅ 只持久化一个 `version` + 时间戳用于增量同步；Set 本体启动时一次性拉（几千词，< 100KB gzip） |
| `aiConfig` | 全局常驻 | provider 列表（掩码 key）、capability → provider 优先级、各 capability 可用性布尔 | ❌ **绝不持久化**（含 key 掩码与端点信息）。每次启动拉一次，用于全站判断「AI 功能是否可用」以决定按钮显隐 |
| **`studySession`** | 跨路由但按日 | 今日会话：`{date, phase, index, queueIds[], answered[], pendingAnswers[], elapsedMs}` | ✅ **localStorage 必须持久化** —— 中断恢复的全部依赖。`date != today` 时启动即丢弃 |
| `player` | 随页面挂载/卸载 | 播放器状态机（`IDLE/LOADING/PLAYING/PAUSED/SEEKING/ENDED`）、`currentCueId`、`loopMode`、`loopRange`、`rate`。**不存 cue 列表**（放组件 `shallowRef`） | ❌ 状态本体不持久化；但 `rate`、字幕档位这类**偏好**写进 `settings`（用户换视频后期望保持 0.75×） |
| `review` | 随页面挂载/卸载 | 当前卡片详情、预取的下一张、评分提交队列 | ❌ 离开 `$reset()`；未提交的答案由 `studySession.pendingAnswers` 兜住 |
| `ui` | 全局常驻 | 侧栏折叠、当前 modal 栈、toast 队列、快捷键作用域栈、全局搜索开关 | ✅ 只持久化「侧栏是否折叠」 |
| `watchProgress` | 全局常驻（轻） | 视频 id → 最后播放秒数（乐观本地写 + 节流上报后端 10s 一次） | ✅ localStorage 兜网络失败，登录后与服务端取 `max` |

**明确不建 store 的东西**：cue 列表、词书全量词表、生词本分页数据、统计图表数据 —— 全部组件局部 `shallowRef` + `useQuery` 式缓存。理由同架构文档：store 里放大对象会导致离开页面后内存不释放，且 devtools 快照会卡。

### 7.2 各页空状态策略

不写具体文案，写策略。统一由 `EmptyState` 组件承载，`primaryAction` 是必填 prop——**任何空状态都必须给出唯一的下一步**。

第一年只做响应式 Web（Non-goals），但背单词是典型移动场景，所以按投入分三档。

## 9. 一致性检查清单（实现时逐条对照）
