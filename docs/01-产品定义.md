# LexiFlow 产品定义

> **TL;DR**
> LexiFlow 有两条并行主线：**词书背单词**（选一本 CET6 / 雅思 / 自导入词书，每天按计划背，打字默写）和**语境采词**（看视频读文章遇到生词，连同那句话和那一秒的原声一起收进来）。
> 两条线汇入**同一个 FSRS 引擎、同一个生词本**，不是两个独立进度条。
> 真正的差异化在两条线的交汇处：**词书里的词，用你自己看过的视频里出现它的那句话当例句** —— 例句不是编的，是你听过的原声。
> 技术栈已定：Spring Boot 3 + MySQL 8 + Redis + Vue 3 + TypeScript + Vite。个人项目，不做付费体系。

---

## 1. 一句话定位

**一个把"系统性背词书"和"从真实语料采词"合并成同一套记忆调度的英语学习平台。**

必须讲清楚为什么是两条线，而不是选一条：

| | 词书驱动（不背单词模式） | 语境驱动（Language Reactor 模式） |
|---|---|---|
| 解决什么 | **覆盖率**：考试大纲、高频词，有明确的"背完"边界 | **鲜活度**：你真实听不懂的那个词，有情绪记忆锚点 |
| 单独用的问题 | 背完的词在真实语料里遇不到，没有正反馈，两周弃用 | 只积累不复习，词汇量增长慢且随机，考试前抓瞎 |
| 用户的真实需求 | "我 6 月要考六级，给我一个能背完的计划" | "这个词刚在播客里听到，我想记住它" |

**这两个需求同时存在于同一个人身上。** 现有产品逼你二选一——扇贝给你词书但语料是编的，Language Reactor 给你语料但没有调度。LexiFlow 的产品判断是：**入口可以有两个，引擎必须只有一个**。

拆开看四个动词：

| 动词 | 含义 | 对应能力 |
|---|---|---|
| **拿到词** | 既可以来自词书的每日计划，也可以来自你正在看的视频 | 词书模块 / 视频精听 / 阅读 / 浏览器插件划词 |
| **收进来** | 入库时带走上下文快照，而不是只存一个单词字符串 | 视频 ID + 时间戳 + 原句 + 译文 |
| **排期** | 由算法决定"今天该复习什么"，不由用户拍脑袋 | FSRS（**两条线共用**） |
| **会用** | 认得 ≠ 会用；必须有产出型练习 | 打字默写、句子听打、影子跟读 |

## 2. 核心闭环

**两个入口，一个引擎。** 所有功能要么在这张图上，要么是为这张图服务的基础设施；不在图上的，进 Non-goals。

```
 ┌─────────────────────────────┐        ┌──────────────────────────────────┐
 │  入口 A：词书背单词          │        │  入口 B：语境采词                 │
 │                             │        │                                  │
 │  选词书（CET6/雅思/自导入）  │        │  看视频 / 读文章 / 全网划词       │
 │        ↓                    │        │        ↓                         │
 │  每日计划（新词 N + 复习 M） │        │  点词查词（本地词典毫秒返回）      │
 │        ↓                    │        │        ↓                         │
 │  认词筛选（认识 → 已知词库） │        │  加入生词本                       │
 │        ↓                    │        │        ↓                         │
 │  学习卡片                    │        │  ★ 上下文快照                    │
 │  音标 / 释义 / 词根 / AI助记  │        │  视频ID + 时间戳 + 原句 + 译文     │
 │        ↓                    │        │                                  │
 │  ★ 例句 ←──── 从你看过的视频里捞 ────────┘  （交汇点，见 §3）           │
 └─────────────┬───────────────┘        └──────────────┬───────────────────┘
               │                                       │
               └───────────────┬───────────────────────┘
                               ▼
                    ┌──────────────────────┐
                    │  统一生词本 user_word │
                    │  source = WORDBOOK /  │
                    │   VIDEO / ARTICLE /   │
                    │   PLUGIN / MANUAL     │
                    └──────────┬───────────┘
                               ▼
                    ┌──────────────────────┐
                    │   FSRS 排期（唯一）   │
                    └──────────┬───────────┘
                               ▼
        ┌──────────────────────────────────────────────┐
        │  多模态复习（结果全部写回 FSRS rating）        │
        │  闪卡 · 打字默写 · 听音拼写 · 选择 · 句子听打 · 跟读 │
        └──────────────────┬───────────────────────────┘
                           ▼
                 复习时回放"那一秒的原声"
                           ▼
              标记掌握 ──► 反哺难度模型与素材推荐
                  │                    │
                  └────────────────────┘
```

**关键在于每一步都不丢信息，以及只有一条排期主干。** 传统流程在语境驱动侧的第三步就把语境扔了（从字幕工具复制单词、粘到 Anki、得到一张裸卡）；在词书驱动侧则是把两套进度分开（词书进度 80%、生词本 200 词，互不相干，用户根本不知道自己到底会多少词）。LexiFlow 全程维持"单词 ↔ 出处"的引用关系，并且**只有一个 due_at**。

## 3. 差异化：两条线的交汇处

单看任一条线，LexiFlow 都不是最好的：词书体验比不过不背单词（人家有精美配图和编辑团队），字幕体验比不过 Language Reactor。**护城河在交汇处。**

### 3.1 例句供给：词书的词，用你自己的语料

不背单词的核心体验是"每个词配真实影视语料例句，带原声"。但它的语料库是**平台预置的、所有人一样的**。LexiFlow 的例句供给按以下优先级：

| 优先级 | 来源 | 为什么更好 |
|---|---|---|
| 1 | **你自己看过的视频里出现该词的那一句** | 有情绪锚点。"这个词在你上周看的那个 TED 里出现过"——记忆强度和陌生例句不在一个量级，而且能听原声 |
| 2 | 全局语料池（其他用户视频挖掘出的公共例句，带原声） | 仍是真实语料 + 真实原声，只是不属于你 |
| 3 | 词典自带例句 | 兜底，无原声 |
| 4 | AI 生成例句 | 最后兜底，**必须在 UI 上标注"AI 生成"** |

**这是双向的：**
- 背词书时 → 系统从你的观看历史里捞例句
- 看视频时 → 系统标出"这句话里有 3 个你正在背的 CET6 词"

第二条比第一条更有价值。它把"背单词"这件抽象的事和"看视频"这件愉快的事绑在了一起：你会因为在视频里认出了昨天背的词而获得正反馈，而这正是所有词书类产品最缺的东西。

### 3.2 具体到体验上

1. 你在 TED 演讲第 4 分 12 秒听到 `trigger`，点一下加入生词本。
2. 三天后复习到这张卡，卡面是那句原话，可以点播放，听到的是**原演讲者的那 3 秒**，不是 TTS。
3. 你打字默写出 `trigger`，一次打对且快，FSRS 收到 Easy，下次间隔拉长。
4. 一周后你在背 CET6 词书遇到 `provoke`，卡片下方例句区自动出现那句 TED 原话（含 `trigger` 的近义语境）和你标记过的那个词。

第 2 步和第 4 步是别人做不到的，因为他们的数据模型里没有那个时间戳，也没有把词书和你的观看历史连起来。

## 4. 三个"不性感但决定生死"的基础设施

这一节单独存在，是因为它们的优先级**高于所有 AI 功能**。AI 功能是加分项，这三样是及格线；缺任何一个，产品都不成立。

### 4.1 FSRS 间隔重复算法

没有它，产品就是个**带登录功能的 Excel**。

用户会记录生词，然后再也不回来看——所有"生词本"类产品死于此。真正提供价值的不是"存下来"，是"在你即将忘记的那天把它推到你面前"。FSRS 相比 SM-2 的收益是同等记忆留存下更少的复习量，对时间紧张的成年学习者是刚需。

两条推论：

1. **任何练习模态都必须把结果写回 FSRS**，不允许存在"独立进度条"。练习是采集记忆信号的手段，不是并行的游戏化系统。
2. **词书进度和生词本进度必须是同一套数据的两个视图**。"CET6 词书完成 42%" 应该是 `count(user_word where wordbook_id=X and state>=REVIEW) / 词书总数` 算出来的，不是单独维护的计数器。

### 4.2 词形还原（lemmatization）

用户点 `running` / `ran` / `runs`，必须都归到 `run`。否则生词本里会出现 5 个"同一个词"，每个都有独立的复习排期，用户第一周就会觉得这产品很蠢然后卸载。

难点不在于调库，在于边界情况：
- 不可还原的专有名词、缩写（`AI`、`NASA`）不能被误还原。
- 词组和短语动词（`give up`、`look forward to`）不能被拆成单词入库。
- 同形异义（`saw` = see 的过去式 / 锯子）需要结合上下文，这是少数值得让 AI 介入的地方。
- 还原结果要和词典条目对得上——还原出一个词典里没有的 lemma 等于没还原。
- **词书场景的额外要求**：词书里给的是 headword（`run`），视频字幕里出现的是 `running`，两者必须能对上，否则 §3.1 的例句供给和"这句话里有你在背的词"都不成立。

### 4.3 本地词典（ECDICT，770 万词条）做主路径

查词是**最高频**的动作，必须毫秒级返回。AI 查词的三个问题让它不能做主路径：

| 问题 | 后果 |
|---|---|
| 慢（2s+） | 点词到看到释义有 2 秒空白，精听节奏被打断，用户会放弃点词 |
| 贵 | 高频动作按 token 计费，个人项目烧不起 |
| 会编释义 | 幻觉出一个不存在的义项，学习类产品里这是致命错误 |

所以分层明确：**本地词典是主路径**（基础释义、音标、词性、词频），**AI 是增值层**（深度解释、助记法、结合当前句子的语境化释义）。AI 层永远异步、永远可降级——AI 挂了，查词照常工作。

**额外的白捡收益：ECDICT 的 `tag` 字段直接就是内置词书。** 它自带 `zk`（中考）/ `gk`（高考）/ `ky`（考研）/ `cet4` / `cet6` / `toefl` / `ielts` / `gre` 标记，配合 `bnc` / `frq` 词频列即可切出按频率排序的内置词书，**零额外数据采购成本，也不碰任何第三方词书的版权**。这一条直接决定了词书主线可以在 S1 就上线。

## 5. 功能清单

分三档。**核心**＝不做就没产品；**重要**＝决定产品好不好用；**增强**＝有余力再做。

### 5.1 核心：词书背单词

这一块单独列，因为它是入口 A 的全部，也是新用户第一天唯一会用的功能（语境驱动需要用户先有素材，词书驱动开箱即用）。

| 功能 | 说明 |
|---|---|
| **内置词书** | 从 ECDICT `tag` 切分：中考 / 高考 / CET4 / CET6 / 考研 / 专四专八 / 雅思 / 托福 / GRE / SAT。每本按 `frq` 词频排序，高频先背 |
| **主题词书** | 商务、计算机、医学、日常口语、学术写作。用 ECDICT 标签 + 词频交叉筛选生成 |
| **自导入词书** | CSV / TXT / Excel / Anki `.apkg`。最小格式 `word`，可选 `translation` / `phonetic` / `example`。导入时对每个词做 lemma 匹配并关联 `dict_entry`，匹配不上的保留自定义释义 |
| **每日计划** | 每日新词数 + 复习数可调（默认 20 新 + 全部到期）。复习量由 FSRS 决定，**不允许用户手动压缩**（压缩就等于放弃调度） |
| **认词筛选（Triage）** | 新词先快速过一遍："认识"→ 直接进已知词库不占学习额度，"不认识"→ 进学习队列。第一次开一本大词书时这一步能省掉一半工作量 |
| **学习卡片** | 单词 / 音标 / 释义 / 词性 / 词频与 CEFR / 词根词缀 / **例句区（按 §3.1 优先级供给，优先带原声）** / AI 助记（按需触发） |
| **打字默写** | 见下方"打字默写的关键设计" |
| **听音拼写** | 只播发音，不给拼写，打出单词。训练音形对应 |
| **选择题检测** | 英→中、中→英、听音选词三种。用于第一次接触和快速过词 |
| **词书进度** | 已学 / 待学 / 已掌握 / 遗忘率，以及**预计完成日期**（按当前速度和 FSRS 负载推算）。这个数字比进度条有用得多 |
| **多词书并行** | 允许同时开多本，但必须指定一本 `primary`。每日新词额度在词书间按用户设定的比例分配 |

**词书与生词本的关系（必须在实现时守住）**：词书里的词一旦进入学习，就是 `user_word` 表里的一行，`source = WORDBOOK`、`wordbook_id = X`。它和你从视频里划的词**在复习队列里完全平等**，混合排期。用户不该看到"词书复习"和"生词本复习"两个按钮——只有一个"今日复习"。

### 5.2 核心：其余

| 功能 | 价值 |
|---|---|
| 视频精听（双语字幕 + 点词查词） | 入口 B 的主体，也是 §3.1 例句池的来源 |
| 单句循环（A-B repeat） | 听不懂的那一句，反复听 10 遍是唯一有效的办法 |
| 字幕三档显隐（双语 / 仅英文 / 全隐藏） | 从"看着懂"过渡到"听着懂"必须有这个梯度 |
| 逐句跳转 | 精听的操作单位是句，不是秒；用进度条拖是折磨 |
| 上下文快照入库 | 差异化的物理基础，没有它 §3 全部无效 |
| 本地词典查词 | 毫秒级主路径（见 4.3） |
| 词形还原 | 生词本不重复、词书与语料能对上的前提（见 4.2） |
| FSRS 排期 + 闪卡复习 | 记忆调度内核（见 4.1） |
| 复习时原声回放 | 别人做不到的那一步 |
| **默认翻译引擎（零配置可用）** | 见 §5.5。新用户不填任何 key 就能看到双语字幕 |

### 5.3 重要

| 功能 | 价值 |
|---|---|
| **句子听打（dictation）** | 训练连读、弱读、语流切分——听力真正的瓶颈不在词汇量 |
| **影子跟读（shadowing）** | 唯一能改善发音和口腔肌肉记忆的练习 |
| **视频里高亮"你正在背的词"** | §3.1 的反向链路，词书与语料互相强化的关键交互 |
| 生词高亮 | 在字幕 / 文章里标出已知词与生词，一眼看到"我为什么听不懂这句" |
| 视频难度标签（CEFR + "你认识 X%"） | 选材是自学最大的坑；90% 已知词的素材才是可听的 |
| 阅读：文章导入 + 划词查词 | 视频之外的第二类语料，覆盖开发者读技术文档的场景 |
| i+1 难度匹配 | 让"下一篇读什么"这个决定不再靠猜 |
| 浏览器插件划词查词 | 把入口铺到全网，优先级高于小程序 / App |
| 已知词库 + 词频分级（COCA/BNC + CEFR） | 难度匹配、素材推荐、认词筛选的数据底座 |
| Anki / CSV 导出 | 降低迁移顾虑，冷启动必备（见 §6） |
| 多模型 BYOK | 进阶用户自配 provider；**不是使用前提**（见 §5.5） |

**打字默写的关键设计**：给出中文释义或播放发音，打出英文，逐字母校验。**打字表现直接映射成 FSRS 的 rating**：

| 表现 | FSRS rating |
|---|---|
| 一次打对且快 | Easy |
| 打对，但慢 / 有退格 | Good |
| 用了提示（首字母 / 长度提示） | Hard |
| 打错 / 放弃 | Again |

这不是一个独立的练习模块加独立进度条，而是**把打字当作一次高保真的记忆检索测量**。打字比"点一下我记得"诚实得多——手指知道你是不是真的会。它同时服务两条线：背词书时它是默写检测，复习生词时它是产出型复习。

**句子听打的关键设计**：数据源就是字幕 cue，不需要额外准备内容。校验必须用**词级 diff**，标出漏词 / 错词 / 多词。逐字符比对是错的：少打一个 `the`，后面全部错位，用户看到满屏红色，学不到任何东西。

**影子跟读的关键设计**：播放原句 → 浏览器 MediaRecorder 录音 → 评分。评分 provider 可插拔：自建 Whisper 只能给**文本准确度**（你说的词对不对），音素级发音评分要接 Azure Speech / 讯飞。这个区别要在 UI 上对用户讲清楚，**不能拿文本准确度伪装成发音分**。

### 5.4 增强

| 功能 | 价值 |
|---|---|
| AI 语境化释义 | 结合当前句子给出"在这里是什么意思"，词典给不了 |
| AI 助记法 | 词根、联想、谐音——对付难词的最后手段 |
| AI 长难句解析 | 拆句子成分，解决"每个词都认识但看不懂"的问题 |
| AI 字幕批量翻译（LLM 精翻） | 机翻质量不够时的升级选项 |
| AI 出题 | 从生词本 / 词书生成选择、填空、翻译、阅读理解 |
| 每日 / 每周总结 | 学了什么、卡在哪、下周该看什么，比排行榜有用 |
| PDF / TXT / MD 导入 | 阅读语料来源的扩展 |
| 词根词缀词族图 | 把孤立的词连成网，对 GRE / 托福阶段收益明显 |

### 5.5 翻译引擎策略：默认免费、零配置可用

**这是一条产品红线：新用户注册后不填任何 API Key，就必须能看到双语字幕。** 让用户"先去申请个 key"是最有效的劝退方式。

所以翻译能力分两层：

| 层 | 用途 | Provider | 用户是否需要配置 |
|---|---|---|---|
| **机翻层**（量） | 整轨字幕翻译、文章段落翻译、词典兜底翻译。追求快和免费，质量够用 | 腾讯 TMT（500 万字符/月免费）、有道、微软 Translator（Azure F0 200 万字符/月免费）、Google Cloud Translation（50 万字符/月免费）、DeepL Free（50 万字符/月）、**自建 LibreTranslate**（完全免费无限，随 Docker Compose 一起起） | **否**。系统预置 |
| **LLM 精翻层**（质） | 点词时的语境化释义、单句精翻、长难句解析、AI 助记。需要理解上下文 | 任何 OpenAI 兼容端点（DeepSeek / Kimi / 通义 / Ollama / vLLM）+ Anthropic / OpenAI | **是**，BYOK |

**地区适配必须内建，不是可选项**：Google 翻译在国内基本不可用（`translate.google.cn` 已停），所以系统预置两条默认链，按用户 region 选：

- `region = CN`：腾讯 TMT → 有道 → 微软 → 自建 LibreTranslate
- `region = GLOBAL`：微软 → Google → DeepL → 自建 LibreTranslate

链上任一环失败自动降到下一环，全挂则退到 LibreTranslate。**LibreTranslate 是最终兜底**——它质量一般，但它保证"开箱即用"这条红线永远不破。

**LLM 翻译不以微调为前置条件。** 第一版使用“当前句子 + 前后文 + 来源标题 + 用户术语表 + 翻译风格”的上下文请求完成语境化翻译；不把文章内容写进模型训练集，也不要求用户先训练一个模型。用户修改过的译文进入反馈数据，用于优化 Prompt、术语表和模型选择。只有当反馈数据足够稳定、且 Prompt/术语表仍无法解决一致性问题时，才评估微调；微调不是主路径，也不能成为产品运行的依赖。

**AI 能力按 capability 分类，不按厂商分类**：`CHAT / TRANSLATE / ASR / TTS / PRONUNCIATION / EMBEDDING`。`TRANSLATE` 同时覆盖系统机翻和用户自配 LLM 精翻，但二者在速度、成本和配置层上分开。每个 capability 下可挂多个 provider，有系统预置的也有用户自配的。理由：这些能力的最优供应商完全不重叠（机翻、LLM、语音识别、发音评分各有强者），按厂商绑定必然会被某一环拖死。

用户可在设置中自行添加 Provider，至少支持：Provider 名称、`base_url`、模型名、API Key、支持的 capability、优先级和降级顺序。**BYOK 是进阶能力，不是使用前提**；未配置 LLM 时，查词、字幕、文章阅读、FSRS 复习和默认机翻仍然可用。

## 6. 明确的非目标（Non-goals）

这一节和功能清单一样重要。个人项目最大的死因是功能蔓延。

| 不做 | 理由 |
|---|---|
| **社交**（打卡分享、排行榜、好友 PK） | 和学习效果无关，是**留存幻觉**。排行榜提升的是打开次数，不是词汇量；而且会引导用户刷简单内容冲数据 |
| **抄袭第三方词书的例句 / 配图 / 释义编排** | 单词表本身是事实性数据（"哪些词属于 CET4"），风险低；但不背单词的例句库、配图、编排是有版权的内容资产。我们的例句来自**用户自己的语料 + 公共语料挖掘 + AI 生成**，这条路必须走干净 |
| **下载 / 转存视频文件** | 版权风险 + 存储成本。只用平台播放器嵌入，视频始终在原平台播放 |
| **UGC 内容社区** | 需要审核、冷启动、运营。单人维护做不了，也不是这个产品的价值来源 |
| **自研 ASR / TTS / 发音评分 / 机翻模型** | 四个独立的工程课题。全部走 provider 抽象，把精力留给闭环本身 |
| **一开始建设模型微调平台** | 翻译首先需要的是上下文、术语和真实反馈，不是训练一个新模型。先记录用户修改与评分，待数据规模和质量足够后再评估；产品主路径不能依赖微调服务 |
| **游戏化**（勋章、等级、虚拟货币、连胜特效） | 唯一保留的是 streak 天数，因为它和 FSRS 的每日到期是同一件事。其余全部不做 |
| **第一年做 App / 小程序** | 浏览器插件性价比高得多：同一套前端栈、没有审核周期、覆盖用户真实学习场景（就在电脑上看视频读文档）。移动端只做响应式 Web |
| **付费 / 订阅体系** | 个人项目。不做支付、发票、退款、会员等级。LLM 成本通过 BYOK 转移给用户，机翻成本走免费额度 |

**一个反直觉的取舍**：Anki / CSV 导出属于"重要"档而不是"增强"档。愿意认真学英语的人大多数已经有一套自己的系统，他们的第一个问题是"我的数据能不能拿出来"。答不上来就没有第二次访问。导出是**冷启动的准入条件**，不是锦上添花。

## 7. 目标用户

不写"所有想学英语的人"。三个具体画像：

### 画像 A：有考试 deadline 又讨厌背词表的大学生

- 大二 / 大三，四六级或考研阶段，词汇量 4000-6000。**有明确的考试日期。**
- 试过百词斩和扇贝，坚持不过两周。原因不是懒，是**背完的词在真实语料里遇不到**，没有正反馈。
- 平时在 B 站看英文影视和 UP 主内容，字幕一关就懵。
- **他要的**：一本能背完的 CET6 词书 + 明确的"今天背 20 个复习 45 个" + 背到的词能在他爱看的内容里被认出来。
- **判断标准**：他会不会连续 30 天打开做完当天的队列。
- **为什么两条线对他都必要**：只有词书他会无聊放弃，只有语境他覆盖不了考纲。

### 画像 B：能读技术文档但听不懂播客的开发者

- 工作 3-8 年，读英文文档 / GitHub issue 无障碍，阅读词汇量上万。
- 听 Lex Fridman、Changelog 或英文技术演讲时只能听懂 60%，一走神就跟不上。
- 短板极不平衡：**阅读词汇 >> 听力词汇 >> 口语词汇**。
- **他要的**：从技术演讲和播客里精听，单句循环把连读听透；跟读练到能开英文会议；**不要给他推 apple / banana**——所以他会用自导入词书或干脆只用语境驱动。
- **判断标准**：一个月后他关字幕能听懂的比例有没有变化。

### 画像 C：雅思 / 托福备考者

- 有明确考试日期和目标分数，愿意每天投入 1-2 小时。
- 卡在听力和口语两项，读写还行。
- 已在用 Anki，但制卡太慢，一场演讲整理下来一小时。
- **她要的**：雅思核心词书 + 听写训练（对应听力填空）+ 跟读训练（对应口语流利度）+ 自动制卡不再手抄例句 + 明确进度可见性。
- **判断标准**：她愿不愿意把 Anki 里的核心流程迁过来。

三个画像的共同点：**词汇量不低，缺的是把"认得"转成"会用"的训练手段**，以及**把系统性覆盖和真实语料连起来的东西**。

| **Anki 的调度生态更成熟** | 插件、社区问题库不是短期能追的 | 不追。提供导出，做"Anki 之前的那一段"——制卡这一段 |

## 9. 风险与约束

### 9.1 合规：字幕来源

抓取 YouTube 字幕，**个人自部署 / 学习项目没问题，公开上线属于 ToS 灰区**。这个风险不能靠"应该没人管"来消化，要在架构上处理：

- 把"平台抓取"做成**可插拔 provider**，随时可以整个摘掉而不影响其余功能。
- 主打链路做成 **URL 解析 + 用户自主上传字幕**（`.srt` / `.vtt` / `.ass`）。抓取只是便利路径，不是唯一路径。
- 不缓存、不转存、不二次分发视频与字幕文件本身，只存用户勾选的那几句上下文快照。
- 视频始终由原平台播放器播放，不代理媒体流。

### 9.2 合规：词书与例句

- **单词表**（哪些词属于 CET4）属于事实性数据汇编，且我们是从开源 ECDICT 的 `tag` 字段切分，来源干净。
- **例句、配图、释义编排**是他人的内容资产，一律不抄。例句只来自：用户自己的语料快照、公共语料挖掘、AI 生成（且标注）。
- 用户自导入词书的内容归用户，默认**私有不公开**，不进公共池。

### 9.3 国内访问：平台与引擎都必须多元

- YouTube 需要代理，**后端抓字幕也要出网**——两条独立网络路径，都要有超时和降级，不能因为抓字幕卡住把整个请求拖死。
- **Bilibili 必须支持**，否则一半用户根本用不了。B 站的字幕接口、鉴权和 AI 字幕质量都与 YouTube 不同，不能假设一套逻辑通用。
- **platform 从第一天就是枚举**：`YOUTUBE / BILIBILI / LOCAL`。`LOCAL` 兜住"本地视频 + 手动上传字幕"这条完全离线可用的路径。
- 翻译引擎同理，见 §5.5 的双默认链。

### 9.4 其他约束

| 风险 | 判断 |
|---|---|
| 功能蔓延 | 最大的死因。Non-goals 一节就是防线，新需求先问"在核心闭环图的哪一步" |
| 两条线做成两个产品 | 第二大风险。守住铁律：**一个 `user_word` 表、一个 `due_at`、一个"今日复习"入口**。一旦出现两个复习按钮，差异化就没了 |
| ECDICT 数据规模 | 770 万词条的导入、索引和查询性能要提前验证，别到最后发现查词要 200ms |
| 机翻免费额度耗尽 | 各家额度都是月度重置。要有用量计数和自动降级链，LibreTranslate 兜底 |
| LLM 成本 | 通过 BYOK 转移；所有 LLM 调用必须可缓存、可降级、非阻塞 |
| 单人精力 | 核心档做完能自用，才有动力做重要档。不允许在核心档完成前碰增强档 |
| 冷启动空状态 | 新用户第一次进来看到空页面就会走。**词书主线正是为此存在**——注册后三步内（选词书 → 设每日量 → 开始背）就能跑通一次完整闭环，不需要先导素材 |

## 10. 优先级顺序（做的顺序）

1. **词典 + 词形还原**：能查、能还原、能对上条目。
2. **生词本 + FSRS + 闪卡**：能存、能排期、能复习。
3. **内置词书 + 每日计划 + 认词筛选**：入口 A 通了。**此时产品已经可自用可示人**（一个能背完 CET6 的工具）。
4. **打字默写 + 听音拼写**（含 FSRS rating 映射）：第一个产出型练习，词书主线的主要检测手段。
5. **默认翻译引擎链**（机翻 + LibreTranslate 兜底）：为视频模块铺路，也保证零配置可用。
6. **视频精听**：字幕、点词、单句循环、上下文快照入库、原声回放。入口 B 通了。
7. **两条线的交汇**：例句从观看历史捞 + 视频里高亮正在背的词。**差异化在这一步才真正成立，不能省。**
8. **自导入词书**（CSV / Excel / Anki）。
9. **浏览器插件划词**：把入口铺开。
10. **阅读 + 难度分级**：第二类语料 + 选材能力。
11. **句子听打**：数据源已有（字幕 cue），边际成本低。
12. **AI 增强层 + BYOK**：上下文翻译、语境化释义、助记和长难句解析；先做 Prompt + 术语表 + 反馈闭环，不做微调依赖。
13. **影子跟读**：依赖第三方评分 provider，放最后。
14. **导出**：成本低可以早做，但不早于第 2 步——没有数据可导。

**微调评估不进入 S1–S7 的主交付路径。** 只有当 `ai_feedback` 中积累了足够多、经过人工确认的“原文 → 用户认可译文”样本，并且可用评测集证明 Prompt、术语表和模型路由仍不足以解决问题时，才单独立项。

判断"做完了"的标准只有一个：**作者自己每天在用它学英语**。个人项目没有 DAU，只有这一个指标。

第 7 步是全表最容易被跳过、也最不能跳过的一步。跳过它，LexiFlow 就退化成"一个还行的背单词器 + 一个还行的字幕工具"，两边都打不过专门做那件事的产品。
