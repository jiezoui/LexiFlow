# 《语脉 · LexiFlow》开发规范与工程准则

> **文档定位**：本项目面向高校高水平软件工程竞赛（全球校园人工智能算法精英大赛）与工业级生产标准，制定本开发规范。团队所有成员（包含 AI 协作助手）在编码、测试、重构与提交过程中必须严格遵守本规范。

---

## 1. 核心架构红线（ArchUnit 守卫铁律）

本项目后端采用 **Java 21 + Spring Boot 3.3 模块化单体（Modular Monolith）** 架构。为了保证模块边界严密、未来可无缝拆分为微服务，制定以下 4 条硬性技术红线：

1. **模块间只能通过 `api` 包通信**：
   * 跨模块调用一律只允许注入目标模块 `api` 包下的 Service 接口；
   * `api` 包中只允许存在接口定义、DTO Record 与业务枚举，**绝对禁止出现 Entity、Mapper 或具体实现类**。
2. **严禁跨模块直接注入别人的 Mapper / Repository**：
   * 任何 `@Autowired XxxMapper` 只能出现在该模块自身的 `internal` 包内，跨模块注入将直接导致 CI/单元测试失败。
3. **每个模块独立拥有数据表，严禁跨模块 SQL JOIN**：
   * 模块间数据解耦，禁止在 MyBatis XML 或 SQL 中编写跨越不同业务模块数据表的 `JOIN` 语句；需要聚合的数据通过应用层编排或预聚合只读表实现。
4. **内部包 `internal` 物理隐藏**：
   * 模块内部的实体类（Entity）、Mapper、ServiceImpl、VO 转换器属于模块私有资产，由 `ArchUnit` 静态分析工具自动做依赖合规性拦截。

## 2. 后端分层与对象流转规范

严格遵循三层架构与明确的对象流转路径：

```
客户端请求 ──► Controller ──► Service ──► Mapper ──► 数据库
 (VO/JSON)  ▲      (DTO)    ▲     (Entity)
            │               │
```

* **Entity（实体对象）**：
  * 存放于 `internal/entity/`，与数据库表结构字段严格一对一对应；
  * **Entity 绝不越过 Service 边界**，禁止 Controller 直接返回 Entity 给前端。
* **DTO（数据传输对象）**：
  * 对外 DTO 存放于 `api/dto/`，内部 DTO 存放于 `internal/dto/`；
  * 一律采用 **Java 17+ `record`** 特性定义不可变对象，杜绝滥用全局 Getter/Setter。
* **VO（视图对象）**：
  * 存放于 `internal/vo/`，专为前端展示定制；
  * 任何敏感字段（如用户的大模型 API Key）必须在 VO 转换阶段完成掩码处理（如 `sk-***abcd`）。
* **事务边界**：
  * 事务控制（`@Transactional`）一律加在 Service 层业务编排方法上，Controller 与 Mapper 层禁止标注事务。

## 3. 前端工程与代码规范

前端基于 **Vue 3 + TypeScript + Vite + Tailwind CSS + shadcn-vue** 搭建，遵循以下原则：

1. **语法规范**：
   * 一律采用 Vue 3 的 `<script setup lang="ts">` 组合式 API（Composition API），禁止使用 Options API；
   * 开启 TypeScript 严格模式（`strict: true`），严禁泛滥使用 `any`，接口返回值必须声明明确类型。
2. **样式与 Token 命名**：
   * 样式统一走 Tailwind 原子类，颜色与间距严格遵循 [06-设计风格与UI规范.md](file:///c:/Users/JieZou/Desktop/AIC/docs/06-%E8%AE%BE%E8%AE%A1%E9%A3%8E%E6%A0%BC%E4%B8%8EUI%E8%A7%84%E8%8C%83.md) 中定义的 CSS 变量（如 `bg-paper`、`text-ink`、`text-accent`）；
   * 禁止在业务组件中手写分散的内联魔数颜色（如 `style="color: #1d9384"`）。
3. **组件划分边界**：
   * `components/ui/`：通用的无业务属性 UI 基础原语（按钮、输入框、Dialog、Tooltip）；
   * `components/word/`、`components/player/`：特定领域业务组件；
   * `views/`：路由页面容器组件，只负责组合业务组件与 Pinia Store 调度，不宜堆砌数千行渲染细节。
4. **高频渲染性能军规**：
   * 视频播放器的字幕同步高亮，一律使用 **`requestAnimationFrame`** 驱动，**严禁使用高频 `setInterval` 或将当前播放毫秒高频写进 Vue 深度响应式 State**（避免 60fps 导致整个页面反复 Re-render）。

## 4. 日志驱动开发原则（“开发日志”更新规范）

为了让团队和用户能够**随时随地精准定位开发进度**，我们推行**“日志驱动开发（Log-Driven Development）”**：

1. **项目根目录常驻 [`开发日志.md`](file:///c:/Users/JieZou/Desktop/AIC/%E5%BC%80%E5%8F%91%E6%97%A5%E5%BF%97.md)**。
2. **每次开发迭代必须包含四个要素**：
   * **时间戳与迭代编号**（如 `2026-09-11 迭代 #01`）；
   * **完成了什么（Done）**：具体创建了哪些文件、实现了什么业务逻辑、修复了什么问题；
   * **做到哪一步了（Current State）**：当前系统所处的里程碑检查点，系统目前能跑通哪些具体流程；
   * **下一步计划（Next Steps）**：下一轮会话/下个任务的具体任务清单，精确到类名或组件。
3. **可验证性**：每条进展必须附带量化的验证方式（如“通过了某个测试用例”、“本地执行了某个命令”、“打开网页可见某张卡片”）。

## 5. Git 提交与版本控制规范

提交信息一律采用 **Conventional Commits** 语义化规范：

* `feat`: 新增功能（如 `feat(dictionary): 支持基于 ECDICT 的 5ms 词形还原`）
* `fix`: 缺陷修复（如 `fix(player): 修复字幕在时间轴跳转时的 100ms 漂移问题`）
* `docs`: 文档变更（如 `docs: 新增算法精英大赛参赛指南`）
* `style`: 样式调整（不影响代码逻辑的排版、Tailwind Token 微调）
* `refactor`: 重构（代码结构优化，未改变对外行为）
* `perf`: 性能提升（如 `perf(cache): 引入 Redis 缓存高频热词查询`）
* `test`: 测试用例（新增 ArchUnit 架构测试或单元测试）
* `chore`: 杂项（构建流程、依赖包升级、环境配置）
