## 1. 文档概述与一句话定位

### 1.1 一句话定位
> **“一个把『系统性背考纲词书』与『真实视频语境采词』打通，用听过的真实原声自动生成复习例句的多模态外语学习平台。”**

### 1.2 解决的本质痛点
现有语言学习产品逼迫学习者在两条路线中二选一，而这两个痛点同时存在于同一个人身上：
1. **词书背诵类（如扇贝、百词斩）**：解决了考试大纲的**覆盖率**，但例句脱离真实语境或纯靠人工编写，背完的词在真实语料里遇不到，缺乏正反馈，两周容易弃用（**“背了遇不到”**）。
2. **语境字幕类（如 Language Reactor）**：解决了语料的**鲜活度**与情绪记忆，但缺乏科学的记忆排期算法，只积累不复习，词汇量增长随机，考前抓瞎（**“遇了记不住”**）。
3. **查词高频痛点**：纯靠商业大模型查词速度极慢（2s+）、容易产生幻觉词义且按 Token 计费成本高昂；离线查词缺乏与上下文结合的深度解释。
4. **练习与复习割裂**：打字拼写、跟读打分往往作为独立游戏化小模块存在，没有把客观练习信号反哺给底层算法，形成了多套互相打架的进度条。

**语脉（LexiFlow）的产品判断：入口可以有两个（词书 / 视频），但引擎必须只有一个（FSRS）；护城河在两条主线的交汇处。**

## 2. 核心业务闭环与护城河交汇点

```
 ┌──────────────────────────────┐         ┌──────────────────────────────┐
 │  入口 A：词书背单词           │         │  入口 B：语境采词             │
 │                              │         │                              │
 │  选考纲词书（CET4/6/雅思等）   │         │  看视频（YouTube/B站/本地）   │

                                 ▼
                     ┌───────────────────────┐

                                 ▼
```

### 2.1 护城河三大杀手锏交汇机制
1. **例句自产自用（原声反哺词书）**：
   * 学习词书里的单词时，例句供给优先级：
     1. **用户自己看过的视频中出现该词的那一句（带原作者原声音频片段）**；
     2. 公共精选语料池（其他用户挖掘出的公共优质视频原声片段）；
     3. 离线词典自带例句（无原声）；
     4. AI 结合语境实时生成（明确标注“AI生成”）。
2. **看视频正向强反馈**：
   * 用户在看视频精听时，系统自动与当前正在背的词书求交，高亮标出：*“这句话里包含了 2 个你正在背的六级核心词”*，极大增强真实场景下的记忆获得感。
3. **一个生词本，一个 due_at**：
   * 词书进度纯粹是派生视图（已学词数 / 词书总数），没有两套并行进度，全站只有一个“今日复习”入口。

## 3. 目标用户画像

* **画像 A：有考试 Deadline 的在校大学生/备考族**
  * 需求：6 月要考 CET-6 或 12 月考研，词汇量 4000~6000，必须有明确的考纲边界和每日任务量（“今天背 20 个新词、复习 45 个”）。
  * 痛点：厌恶传统词表死记硬背，爱看 B 站/YouTube 英文视频但脱离字幕看不懂。需要两者的有效连接。
* **画像 B：进阶外语自学者/技术工程师**
  * 需求：阅读英文技术文档、看海外开源发布会/技术演讲，遇到生词想一键摘录，并希望系统在科学的时间点推出来复习，通过打字默写形成肌肉记忆。

## 4. 需求分级清单与功能详细规范

根据开发阶段与竞赛评审要求，功能按 **P0（核心闭环）/ P1（多模态与AI亮点）/ P2（扩展与开源加分项）/ P3（非目标）** 严格分级。

### 4.1 【P0 级】核心基础设施与主干闭环（MVP 必做）

#### 功能 1：离线本地词典（ECDICT）与毫秒级查询
* **数据基础**：全量导入 770 万开源词典条目（ECDICT），包含音标、英汉释义、柯林斯星级、BNC/FRQ 词频、考试大纲标签（zk/gk/ky/cet4/cet6/ielts/toefl/gre）。
* **性能要求**：精确与前缀查询 P95 < 30ms（Redis 缓存命中 < 5ms）。绝不允许首屏查词走大模型网络请求。
* **分级展示**：默认展示权威离线释义；AI 助记与语境化分析作为异步增值折叠卡片。

#### 功能 2：离线词形还原引擎（Lemmatization）
* **核心机制**：解析 ECDICT 的 `exchange` 构词变换字段，构建正反向映射倒排索引表 `dict_form_index`。
* **功能边界**：输入变体形式（如 `running`、`ran`、`better`、`analyses`），系统在 5ms 内精准还原到原形词元（`run`、`good`、`analysis`），并在前端给出变形标签（“过去式”、“比较级”）。
* **业务价值**：防止生词库产生多个变体孤立词卡，确保视频字幕提取的词汇与考纲词书精准对齐。

#### 功能 3：统一 FSRS 间隔重复调度引擎
* **算法内核**：实现 **FSRS 现代间隔重复算法**，抛弃陈旧的 SM-2。
* **状态机与核心指标**：为每个词维护 `Difficulty`（难度）、`Stability`（稳定性）、`Retrievability`（可提取度）及 `due_at`（下次复习时间戳）。
* **全站单入口**：不论词汇来自词书还是视频，统一汇聚在 `/study` 调度中枢，单日到期量由算法严格推算，禁止用户手动跳过算法压缩进度。

#### 功能 4：打字默写（行为动力学映射到 FSRS）
* **交互流程**：系统呈现中文释义或播放发音，用户在无拼写提示下敲击键盘打出英文，逐字母实时校验。
* **核心自研创新（客观行为映射机制）**：
  * **一次拼对且极速**（无退格、未用提示、耗时处于基线时长内） $\to$ 自动评定为 **`Easy (4)`**；
  * **拼写正确但有退格/迟疑** $\to$ 自动评定为 **`Good (3)`**；
  * **使用了首字母/长度提示后拼对** $\to$ 自动评定为 **`Hard (2)`**；
  * **拼错或放弃** $\to$ 自动评定为 **`Again (1)`**。
* **价值**：将打字练习转化为客观、高保真的记忆信号采集器，替代用户主观打分。

#### 功能 5：视频精听与语境快照采集
* **视频支持**：支持嵌入 YouTube IFrame、Bilibili 播放器及本地音视频文件。
* **字幕机制**：支持解析 VTT / SRT / ASS 双语字幕，使用自研外层 DOM 结合 `requestAnimationFrame` 实现毫秒级高亮跟随。
* **单句控制**：快捷键实现单句 A-B 循环播放、上一句/下一句快速跳转、字幕三档显隐（全隐藏 / 仅英文 / 双语）。
* **一键语境采词**：点击字幕单词即触发 `WordPopover` 查词弹窗，点击“加入生词本”时，自动抓取并绑定**上下文快照**：`{ 视频ID, 开始毫秒, 结束毫秒, 英文原句, 中文翻译 }`。

#### 功能 6：双向交汇反哺机制
* **原声例句卡片**：在背词书卡片底部，系统自动检索该词是否存在于用户的“观看历史字幕库”中，若存在则直接渲染为首选原声例句，提供“播放 3 秒原声”按钮。
* **字幕反向高亮**：进入视频播放页时，前端自动拉取用户当前正在背的词汇 Lemma 集合，字幕自动高亮标出正在背诵的生词。

### 4.2 【P1 级】AI 赋能与多模态亮点（竞赛夺奖王牌）

#### 功能 7：影子跟读（Shadowing）与开源语音评测
* **交互闭环**：播放原视频 3~5 秒原声台词 $\to$ 浏览器 MediaRecorder 录音 $\to$ 提交语音模型评测 $\to$ 输出诊断报告。
* **开源 AI 评测方案**：
  * 基于开源端到端语音识别模型（OpenAI Whisper / 阿里 SenseVoice）做带时间戳转录；
  * 自研**基于 Levenshtein 动态规划的词级对齐算法（Word-level Forced Alignment）**；
  * 准确定位并高亮：**漏读（Omission，灰色）**、**误读（Substitution，红色）**、**多读（Insertion，黄色）**；
  * 输出综合发音分，并将跟读表现映射更新至 FSRS 记忆模型。

#### 功能 8：开源离线机翻容器（零配置可用红线）
* **产品红线**：新用户注册后无需配置任何商业 API Key，必须立刻能看整轨双语字幕。
* **分层翻译链机制**：
  * **国内环境（CN）**：腾讯 TMT $\to$ 有道 $\to$ 微软 Translator $\to$ **自建 LibreTranslate 兜底**；
  * **海外环境（GLOBAL）**：微软 $\to$ Google $\to$ DeepL $\to$ **自建 LibreTranslate 兜底**。
* **LibreTranslate 容器**：随 Docker Compose 离线启动，作为终极兜底保障，实现数据私有可控。
* **双语字幕时间轴贪心对齐**：针对官方中英字幕条数和时间轴不一致问题，通过“时间区间重叠度占比”算法自动对齐合并。

#### 功能 9：LLM 语境化精翻与语法助记（BYOK）
* **定位**：高级增值层，用户自带 Key（BYOK），密钥经 AES-GCM-256 加密存库。
* **功能项**：
  * **语境化释义**：结合视频前后 3 句话的剧情上下文，指出该词“在此处的最准确含义”；
  * **长难句拆解**：语法成分划分（主谓宾、从句、倒装）；
  * **AI 记忆法**：基于词根词缀、图像联想或谐音生成专属助记 Prompt。

#### 功能 10：按每日待复习词量身定制短文（Story Mode · AI 语境自适应串词生文）
* **业务价值**：解决传统背词“字典效应”（孤立单词背诵难以迁移至长文理解）。将用户今日 FSRS 队列中的 15~20 个待复习词或新词，动态编织为一篇通畅、生动且难度可控的情境短文。
* **算法架构与实现机制**：
  * **语义拓扑聚类（Semantic Clustering）**：利用轻量开源 Embedding（`bge-small-en` 或 `Sentence-BERT`）计算今日词表余弦相似度，聚类为 1~2 个语义簇，自适应匹配最佳叙事框架（科技评论、悬疑故事、科幻短篇）；
  * **CEFR 可读性与背景词过滤网**：严格约束生成短文中的非目标词汇难度低于用户认知水平（如 CET-4 词汇骨架点缀 CET-6 待背词），防止背景词难度倒挂；
  * **受约束结构化输出（JSON Schema）**：模型输出带精确段落与生词字符偏移量（`offset`）的结构化数据，确保生词 100% 出现且词性语境匹配；
  * **后验验证循环（Self-Correction Loop）**：自动校验生词覆盖度与语法正确性，未通过自动触发微调重写；
  * **阅读联动与 FSRS 反哺**：前端在 `/reading` 沉浸式阅读器中呈现，支持划词即查与开源 TTS 伴读；阅读完成后自动对涉及词汇记录一次“语境识记反馈”，推动 FSRS 稳定性提升。

#### 功能 11：句子听打练习（Dictation）
* **数据来源**：直接取材自视频已解析的 Subtitle Cue。
* **评测机制**：盲听原声后逐词打出完整句子，系统执行**词级 Diff**（严禁逐字符报错导致的错位全红），提示拼错词与介词漏听。

### 4.3 【P2 级】开放成果与扩展加分项（竞赛开源指标）

#### 功能 12：独立 Chrome 浏览器划词插件
* **形态**：独立的浏览器扩展程序（Manifest V3），可在网页浏览、外刊阅读、GitHub 阅览时划词查词。
* **互通**：与 Web 端共享登录态，划词内容直接带上网页 URL 与上下文段落，推入用户生词本。

#### 功能 12：开源数据与脚本资产包
* **开放成果交付**：
  * 开源“ECDICT 快速导入与词形还原反查表提取脚本”；
  * 开源“双语字幕重叠时间轴归并与预分词 Tokenizer 工具”。

#### 功能 13：多语种架构预留证明
* 数据库核心表全面配置 `language` 列；
* 预留分词器抽象，支持无缝替换为日语分词引擎（Kuromoji/MeCab）与 JMdict 日语词典，提供 1 组生肉日剧学习演示用例。

### 4.4 【P3 级】明确非目标（Non-goals，严格不做）

| 坚决不做的事项 | 剔除原因 |
|---|---|
| **转存 / 下载视频源文件** | 产生高昂的对象存储与带宽成本，且存在版权侵犯风险。采用官方 IFrame 嵌入播放。 |
| **社交系统（好友PK、排行榜、动态广场）** | 虚假留存功能，与个人学习效果无关，容易导致刷题刷榜。仅保留学习 Streak 连续天数。 |
| **自建大模型私有化微调平台** | 语境化翻译通过丰富的上下文 Prompt 即可达到优秀效果，微调维护成本与硬件门槛极高。 |
| **商业付费、发票、会员等级体系** | 个人全栈与开源竞赛定位，杜绝一切付费墙与商业化包袱。 |
| **第一年开发原生 iOS / Android App** | 单人研发精力有限，跨平台成本高。优先保证 Web 响应式体验与 Chrome 桌面端插件。 |

## 5. 页面分布与核心信息架构

系统设计为 **5 个主导航入口**，结构极为克制，杜绝臃肿：

```
[ 顶部/侧边主导航 ]
├── 1. 今日 (Dashboard /)        → 今日概览、学习统计、Streak、开始今日学习
├── 2. 词书 (/wordbooks)         → 内置考纲词书、我的词书、每日进度与预计完成日
├── 3. 生词本 (/vocab)           → 全部生词列表、按来源/掌握度筛选、单词语境详情
├── 4. 视频 (/videos)            → 视频精听库、导入视频、播放器与双语字幕精听
├── 5. 阅读 (/reading)           → 导入文章、划词阅读、难度分级
└── [ 辅助配置入口 ]
    ├── 今日调度中枢 (/study)    → 认词筛选 → 学习卡片 → 打字默写 → 影子跟读
    └── 设置中心 (/settings)     → 翻译引擎降级链设置、LLM BYOK 密钥配置、快捷键绑定
```

### 关键交互页面规范
1. **`/` 今日概览页**：展示今日待复习量（FSRS 计算值）、主词书背完倒计时、连续打卡天数，一键直达“今日学习”。
2. **`/study` 调度中枢**：无独立落地停留页，采用状态机编排：`认词快筛 (Triage) → 新词初识 (Learn) → FSRS复习 (Review) → 打字默写 (Typing)`。
3. **`/videos/:id` 视频精听页**：左侧/上方视频播放器，右侧/下方双语同步字幕；支持划词弹层、单句 A-B 循环与快捷键调控。

## 6. 技术规格与性能指标（NFR）

### 6.1 技术选型基线
* **后端工程**：Java 21（启用虚拟线程 Virtual Threads Loom）+ Spring Boot 3.3。
* **架构模式**：**模块化单体（Modular Monolith）**，划分 10 个独立业务模块，使用 `ArchUnit` 实施物理代码包隔离（严禁跨模块 Mapper 注入与跨表 JOIN）。
* **数据存储**：
  * **MySQL 8.4**：`utf8mb4_0900_ai_ci` 字符集，配置 `ngram` 全文索引，JSON 字段存储预分词 Token；
  * **Redis 7**：ECDICT 热词缓存、令牌桶限流、JWT 刷新黑名单。
* **前端工程**：Vue 3 + TypeScript + Vite + Tailwind CSS + shadcn-vue。
