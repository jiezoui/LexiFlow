# LexiFlow 跟读评测模块优化报告

日期：2026-10-08

范围：`speech-bridge` 发音评分、FastAPI 接口、跟读页面反馈与评测验证。
目的：供技术报告第四章“算法设计”、第五章“实验验证”和第六章“创新与局限”更新使用。

## 1. 结论与证据边界

本次将线上音素评分从“CTC 前向—后向状态占用后验 + 排名”切换为“CTC Viterbi 对齐 + 目标音素发射概率”。选择依据是**此前已完成**的 SpeechOcean762 组件实验：Viterbi 在 500 条测试录音上的句级 MAE 为 11.12，原 FB+Rank 为 15.91；两者 Pearson 相关系数分别为 0.5379 和 0.5316。Viterbi 的整体音素严重错误 F1 为 0.3535，FB+Rank 为 0.3278。该结果说明已有测试条件下 Viterbi 更适合作为当前默认评分器，但**不是本次改动后重新获得的独立测试成绩**。

本次新增了录音与证据质量门控、错误提示收敛、词级降级显式标记，以及一轮真实录音产品链路诊断。最终版本在 12 条既有开发集录音中有 10 条完成评分、2 条要求重录；10 条的音素对齐覆盖率均为 100%。这轮小样本只证明链路可运行，并暴露了 ASR 误识别边界，不能用于宣称总体评分精度提升。

## 2. 原方案的问题

原音素分把“给定参考音素串时，该状态占据某帧的后验峰值”映射成高分，再融合帧内排名。该后验衡量的是**在强制接受参考串条件下的对齐确定性**，不等于“读对了这个音素”的概率。此前实验中，FB+Rank 对低人工分录音系统性高估：人工准确度低于 60 分的 46 条录音，FB+Rank 平均高估约 44.11 分；Viterbi 平均高估约 11.42 分。原代码还在参考音素数多于音频帧数时抽稀音素，这会产生看似完整、实际已丢目标音素的诊断。

另外，原线上 ASR 把参考句作为 `initial_prompt`，可能将漏读词提示进转写；音素模型失效后仍把缺失音素计成 0 分，形成伪错误；即使 ASR 转写与参考句几乎不匹配，也会汇总出三维分数。旧界面用 55 分作为“严重音素问题”阈值，与开发集上选择的 Viterbi 阈值 8 分不一致。

## 3. 修改后的算法流程

```text
16 kHz 单声道录音
  → 裁首尾静音与输入质量检查
  → Whisper 转写（不注入参考句）
  → 参考词与转写词动态规划匹配
  → 匹配证据不足时要求重录
  → espeak-ng 生成参考音素并检查词表覆盖
  → wav2vec2 帧级 log-softmax
  → CTC Viterbi 强制对齐
  → 仅对 ASR 精确匹配的词给出音素声学反馈
  → 准确度、完整度、流利度汇总
```

### 3.1 音素对齐与打分

设参考音素序列为 `y₁…yₙ`，模型帧级对数概率为 `log pₜ(k)`。CTC 状态串按 `blank, y₁, blank, …, yₙ, blank` 展开。Viterbi 递推在保留、前进一步与允许的跨 blank 跳转中选最大概率路径；相邻同一 token 不允许直接跨 blank。若音频帧数 `T < n + 相邻重复 token 对数`，直接判定无法完整对齐，**不抽稀参考串**。

对第 `i` 个参考音素，取最优路径分配的帧集合 `Fᵢ`：

```text
qᵢ = exp( mean_{t∈Fᵢ} log pₜ(yᵢ) )
Pᵢ = clip( 100 × (log qᵢ + 6.9) / 6.85, 0, 100 )
```

`qᵢ` 是目标 token 帧级概率的**几何均值**，`Pᵢ` 是启发式映射分，不是正确发音概率。现有响应字段 `posterior` 为兼容前端保留，Viterbi 模式下承载 `qᵢ`；接口同时返回 `engine.scoring_method = viterbi_ctc`，避免误读为旧方法的 CTC 状态占用后验。旧前向—后向方法继续保留，供对照和数值复核。

严重音素问题采用先前 SpeechOcean762 开发集选定的 **`Pᵢ < 8`** 筛查阈值；它针对该数据集“人工音素分低于 1/2”的标签。界面称为“声学证据较弱”，要求用户回听核对，不声称识别出确定的具体替换音素。只有词级 ASR 与参考词精确匹配时，才展示该词的音素诊断；替换词或漏读词只给词级反馈。

### 3.2 三维分数与可靠性门控

三维权重暂保留现有业务公式，以隔离本轮音素评分器变更：

```text
准确度 = 0.55 × 已评音素均分 + 0.30 × 词级相似度 + 0.15 × ASR 词置信度
总分   = 0.50 × 准确度 + 0.30 × 完整度 + 0.20 × 流利度
```

当没有可用音素分时，原有词级降级公式仍返回参考分，但会标记 `word_level_fallback`；前端**不将此类结果写入练习历史或今日打卡**。准确度、完整度和流利度权重仍属启发式参数，尚未按人工三维评分做产品链路标定，不应把总分解释为标准化能力等级。

| 检查 | 当前处置 |
| --- | --- |
| 裁剪后有效音频短于 0.25 秒 | HTTP 422，请重录 |
| RMS 低于 −45 dBFS | HTTP 422，请靠近麦克风 |
| 绝对幅度 ≥0.985 的样本超过 5% | HTTP 422，提示削波 |
| ASR 无转写词 | HTTP 422，请重录 |
| 四词以上句子与参考词精确匹配率低于 25% | HTTP 422；无法区分读错与 ASR 误识别 |
| G2P 不可用、音素词表或对齐覆盖率低于 90%、模型异常 | 明示词级降级；不制造音素错误，不计入正式练习历史 |

其中音量、削波、词匹配和覆盖率阈值是保守的工程门控，**未用独立人工数据完成阈值校准**。HTTP 422 返回机器可读 `code` 与中文 `error`；前端显示重录原因。结果中的 `engine` 还记录评分方法、音素覆盖率、降级原因、参考词匹配率，以及 ASR 是否使用参考句提示。

## 4. 验证结果

### 4.1 已有组件对照实验（本次选型依据）

SpeechOcean762：开发集 100 句、官方测试来源的 500 句，测试集 125 名说话人、9,483 个参考音素。此实验使用数据集自带的 ARPABET 标注映射到模型 IPA token，比较的是**声学评分组件**，未经过线上 espeak-ng G2P、三维融合或前端。

| 方法 | Pearson r | 句级 MAE（分） | 严重音素错误 F1 |
| --- | ---: | ---: | ---: |
| ASR 词编辑距离 | 0.4316 | 19.61 | 0.2567 |
| CTC Viterbi | **0.5379** | **11.12** | **0.3535** |
| 原 FB+Rank | 0.5316 | 15.91 | 0.3278 |

按说话人聚类 bootstrap，`FB+Rank − Viterbi` 的 Pearson 差值 95% 区间为 `[-0.0239, 0.0111]`，不能证明相关性有稳定差别；MAE 差值区间为 `[3.05, 6.69]` 分，原方法在已有测试上的绝对误差更大。Viterbi 的严重音素错误检出有 216 真阳性、610 假阳性、180 假阴性，精确率约 26.2%、召回率约 54.5%，因此具体音素提示必须保持审慎。

**重要限制：**这些 500 条测试结果已被用于本次方法选择，不能再把它们当作新版本的“未见独立测试集”。此外，旧 FB+Rank 在 `/θ/–/s/` 与 `/iː/–/ɪ/` 参考音组的 F1 局部更高；分组并不证明模型识别了确切的音素替换关系。

### 4.2 本次代码与接口验证

- `unittest`：6 项通过，包括小型 CTC 穷举最优路径、重复 token 帧数不足、静音/削波/短录音、模型故障不产生伪音素错误、内容严重不匹配时停止评分，以及 API 对静音返回 422。保留的前向—后向算法另有 48 组穷举数值对拍，最大状态后验误差约 `1.44×10⁻¹⁵`。
- TypeScript：`node node_modules/typescript/bin/tsc --noEmit` 通过。
- 本地 REST 自检：`/health`、`/phonemes`、`/score_pronunciation` 均成功；合成参考音的 19 个词全部匹配，音素对齐覆盖率 100%。合成音仅验证连通性，不能用于人类发音准确率主张。
- 真实录音产品链路诊断：从**已有开发集**按人工准确度排序等距取 12 条，10 条评分、2 条因参考词匹配率低于 25% 要求重录。10 条评分结果全部使用 `viterbi_ctc`，参考音素对齐覆盖率均为 100%；共对 149 个精确匹配词内的音素给出评分，其中 20 个被阈值筛为声学证据弱。已预热后的单条评分耗时中位数约 2.15 秒。此样本量和取样方式只供链路诊断，不提供统计精度结论。

两个要求重录的例子分别有人工准确度 30 和 80 分；后者说明转写失败可能使本来较好的发音被误判。因此门控选择“不给正式分数”，而不是把 ASR 不确定性当作发音错误。

原始组件实验结果见 `reports.local/figures/speech_benchmark_results.json` 与 `speech_confidence_intervals.json`；本次真实录音逐条诊断见 `reports.local/speech_v2_product_smoke.json`。这些本地结果目录默认不提交 Git。复现脚本分别为 `scripts/eval_speech_benchmark.py`（已有组件实验）与 `scripts/eval_shadowing_product_smoke.py`（本次产品链路诊断）。

## 5. 可直接写入技术报告的表述

**第四章算法设计：**“系统以开源 wav2vec2 音素 CTC 模型提供帧级概率，以 espeak-ng 生成参考音素，采用自主实现的 CTC Viterbi 动态规划求参考串的最优合法对齐路径。对每个参考音素，计算路径所属帧的目标 token 对数概率均值，经固定单调映射生成声学分。Whisper 提供不带参考句提示的词级转写；系统只对词级匹配正确且音素对齐可靠的词输出音素反馈。录音质量、内容匹配与音素覆盖率门控限制不可信评分。”

**第五章效果验证：**“先前 SpeechOcean762 组件实验中，Viterbi 在 500 条测试录音上的 Pearson r 为 0.5379、MAE 为 11.12、整体严重音素错误 F1 为 0.3535；原 FB+Rank 对应为 0.5316、15.91、0.3278。本轮据此选用 Viterbi 作为线上默认声学评分器，并以穷举 CTC 路径测试验证实现。另在 12 条既有开发集录音上验证真实产品链路，10 条成功、2 条因内容证据不足拒绝给正式分数。组件实验与产品链路诊断使用不同评价口径，不能合并成单一效果提升结论。”

**第六章创新与边界：**“项目自主贡献在于开源模型之上的对齐、证据筛选、分维汇总和可解释反馈流程，而非从零训练声学模型。当前音素和三维权重仍为启发式设计，具体音素纠错的精确率有限；后续需用全链路、独立人工评分数据校准，并测量拒评覆盖率与评分误差的权衡。”

## 6. 后续研究任务

1. 冻结当前评分器、质量门控、G2P 和 ASR 版本，采集**新的**未见人工评分录音；按说话人划分开发集和测试集，避免沿用已看过的 500 条测试集反复调参。
2. 同时评估完整产品路径的准确度、完整度、流利度、总分 MAE/相关性，音素错误精确率/召回率，以及拒评率、重录原因、运行耗时。对被拒录音也保留在分母中。
3. 公平比较“有/无 ASR 参考提示”、“Viterbi/FB+Rank”、“仅词级/声学+词级”，所有候选只在开发集选参数；最终只对独立测试集评估一次。
4. 对原准确度公式中的 ASR 置信度 15% 和三维权重做人工标签标定；若不能提高未见样本表现，维持本版并报告适用边界。音素提示可另做双人盲审，验证其是否真正有助于学习者纠错。
